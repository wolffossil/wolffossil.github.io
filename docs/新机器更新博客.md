# 在另一台电脑上 clone 并更新博客

> 目标:在一台**全新电脑**上拉下博客、写文章/改配置、预览、推送触发自动部署。
> 技术栈:Hugo(extended) + hugo-theme-stack(git submodule) + GitHub Actions。

---

## 一、装依赖(只做一次)

### 1. Git
macOS 自带,或 `brew install git`。

### 2. Hugo —— 必须 extended 版,且版本对齐 CI

CI 用的是 **Hugo `0.164.0` extended**(见 `.github/workflows/deploy.yml` 里的 `HUGO_VERSION`)。本地最好一致,避免"本地好、线上挂"。

```bash
# macOS
brew install hugo
hugo version    # 确认输出含 "extended";版本尽量接近 0.164.0
```
> 主题 v4.0.3 要求 Hugo ≥ 0.157。若 brew 版本过高导致异常,可到 https://github.com/gohugoio/hugo/releases 下载指定版本的 `hugo_extended_*`。

### 3.(可选)配置 GitHub 认证
如果这台机器也有多个 Git 账号,按《发布指南-多账号push.md》配好个人账号的 SSH key + `~/.ssh/config` 别名。
**单账号的干净机器**可直接用 `git@github.com:...` 或 HTTPS。

---

## 二、Clone(务必带上子模块)

主题是 git submodule,**必须递归克隆**,否则 `themes/` 是空的、构建会失败:

```bash
# 多账号(用别名):
git clone --recurse-submodules git@github-wolffossil:wolffossil/wolffossil.github.io.git

# 单账号:
git clone --recurse-submodules git@github.com:wolffossil/wolffossil.github.io.git
# 或 HTTPS:
git clone --recurse-submodules https://github.com/wolffossil/wolffossil.github.io.git

cd wolffossil.github.io
```

**如果忘了 `--recurse-submodules`**(发现 `themes/hugo-theme-stack/` 是空的):
```bash
git submodule update --init --recursive
```

**设置本仓库身份**(多账号机器必做,避免用错邮箱):
```bash
git config user.name  "wolffossil"
git config user.email "你的GitHub个人邮箱"
```

## 三、本地预览

```bash
hugo server -D        # -D 包含草稿(draft: true 的文章)
```
浏览器打开终端提示的地址(默认 `http://localhost:1313/`)。改动文件会自动热更新。

---

## 四、写 / 改内容

### 新建文章(推荐 page bundle 方式:一篇一个文件夹,图文放一起)
```bash
hugo new content post/我的新文章/index.md
```
生成的 `content/post/我的新文章/index.md` 顶部是 front matter:
```yaml
---
title: "我的新文章"
date: 2026-07-22T10:00:00+08:00
draft: true          # 写完发布前改成 false,或删掉这行
categories: ["随笔"]
tags: ["标签1", "标签2"]
image: cover.jpg     # 可选:封面图,放同文件夹
---

正文……
```

### 插入图片(重要,踩过坑)
- 把图片**放进文章同一个文件夹**,markdown 里用相对路径:`![说明](my-pic.png)`。
- ⚠️ **文件后缀必须与真实格式一致**。新版 Hugo 图片处理很严格,后缀谎报(比如把 WebP 命名成 `.png`)会直接报 `image: unknown format` 构建失败。
  - 检查真实格式:`file 图片名`
  - 就地转换(macOS):`sips -s format png 输入 --out 输出`

### 改主题外观 / 自定义样式
统一写在 `assets/scss/custom.scss`(会覆盖主题占位),**不要去改 `themes/` 里的文件**。

### 改站点配置
编辑根目录 `config.yaml`。

## 五、发布

```bash
hugo server -D            # 本地确认无误
# Ctrl-C 停掉预览

git add .
git commit -m "post: 我的新文章"
git push                  # 触发 GitHub Actions 自动构建部署
```
到仓库 **Actions** 标签页看构建;绿勾后 `https://wolffossil.github.io` 即更新。**无需本地手动 `hugo` 构建**——那是 CI 的活。

## 六、更新主题(可选,想升级 stack 主题时)

主题跟随官方 `CaiJimmy/hugo-theme-stack`,升级只是"挪动子模块指针":

```bash
# 拉官方默认分支最新
git submodule update --remote themes/hugo-theme-stack

# 本地验证能正常构建(留意主题大版本升级可能需要改 config)
hugo server -D

# 确认无误后提交这个新指针
git add themes/hugo-theme-stack
git commit -m "chore: 升级主题"
git push
```
> 升级若跨大版本(如 v4 → v5),config 可能有破坏性变更,参考本仓库两次 commit 记录里 v3→v4 的迁移做法。

想锁定到某个具体 tag 而非最新:
```bash
cd themes/hugo-theme-stack
git fetch --tags
git checkout v4.0.3        # 换成目标 tag
cd ../..
git add themes/hugo-theme-stack && git commit -m "chore: 主题锁定 v4.0.3"
```

## 七、多机器协作:动手前先同步

在多台机器间来回改,每次开工前先拉最新(含子模块):
```bash
git pull
git submodule update --init --recursive   # 同步主题指针
```

## 速查表

| 操作 | 命令 |
|------|------|
| 克隆(带主题) | `git clone --recurse-submodules <url>` |
| 补拉主题 | `git submodule update --init --recursive` |
| 本地预览(含草稿) | `hugo server -D` |
| 新建文章 | `hugo new content post/xxx/index.md` |
| 发布 | `git add . && git commit -m "..." && git push` |
| 升级主题 | `git submodule update --remote themes/hugo-theme-stack` |
| 查图片真实格式 | `file 图片名` |
| CI 构建进度 | 仓库 → Actions 标签页 |

## 常见坑

| 现象 | 解决 |
|------|------|
| `themes/hugo-theme-stack` 空的、构建报缺主题 | `git submodule update --init --recursive` |
| `image: unknown format` | 图片后缀与真实格式不符,用 `file` 查、`sips` 转 |
| 本地正常但线上构建挂 | 本地 Hugo 版本与 CI(`0.164.0`)差异大,对齐版本 |
| 文章不显示 | front matter 里 `draft: true` 没改 false;或文章不在 `mainSections`(=`post`)下 |
| push 认证失败 | 见《发布指南-多账号push.md》 |
